# Glossary

Vocabulary of the Arbore domain. Every business term, iOS technical term, or internal shorthand must have an entry so that a new developer can be onboarded in under ten minutes.

Convention: alphabetical order, **term** in bold, definition of one to three sentences.

---

## AR (Augmented Reality)

Augmented reality — overlaying virtual objects (3D plants) onto the camera feed. On iOS, it relies on **ARKit** (tracking, plane detection) and on **SceneKit** (current rendering) or **RealityKit** (target, see issue #83).

## ARWorldMap

**ARKit** serialization of the state of an AR session (feature points and anchors). Saved to disk per garden (`worldmap_{id}.arworldmap`), it is reloaded when the garden is reopened to place the plants back at the same coordinates. Very sensitive to lighting changes between sessions (see issue #96).

## Anchor (ARAnchor)

Fixed point attached to a position in the real world, tracked by ARKit. Each placed plant is associated with an `ARAnchor`. Anchors are serialized in the WorldMap to ensure persistence across sessions.

## ARQuality

Swift enum (`full`, `standard`, `lite`) defined in `ARGarden/Quality/ARQuality.swift`. Sets the value of `environmentTexturing` when an AR session starts. `ARQuality.recommended` aggregates the device tier (see `DeviceCapabilities`) and the current `ProcessInfo.thermalState` to decide on the selected level. The choice is frozen for the entire duration of the session — changing `environmentTexturing` mid-session would require a `resetTracking` that would lose the relocalized `ARWorldMap`.

## Boundary

Closed polygon on the ground that delimits the garden area. Drawn by the user in `gardenPerimeter` mode (non-LiDAR) or derived from the **RoomPlan** scan (LiDAR). Represented in memory as `[SIMD3<Float>]`.

## C4 Model

Four-level architecture model (**C**ontext, **C**ontainer, **C**omponent, **C**ode) defined by Simon Brown. Applied to Arbore in [`architecture/`](architecture/). The Code level is intentionally omitted: the source code serves that purpose.

## DeviceCapabilities

Device tier detector in `ARGarden/Quality/DeviceCapabilities.swift`. Uses `ProcessInfo.processInfo.physicalMemory` to classify the current iPhone as `.legacy` (< 4 GB of RAM, e.g. iPhone XR) or `.modern` (≥ 4 GB, iPhone XS and later). Deliberately based on physical RAM rather than on hard-coded iPhone model strings, to stay future-proof with each new generation.

## Hero screen

Main, complex screen that warrants dedicated per-screen documentation. For Arbore: `GardenARPlacementView`, `QuestionnaireView`, and `PersonalDetailsView`. Simple screens (a button, a navigation) are not considered hero screens and do not have a dedicated spec.

## ICP (Iterative Closest Point)

Registration algorithm between two point clouds or meshes. Computes the rigid transformation (rotation and translation) that minimizes the distance between correspondences. Considered for **scene-to-scene registration** (issue #140) as an alternative to ARWorldMap reloc-pose.

## Manual Replace

Manual plant re-placement flow activated when ARWorldMap relocalization fails. The user retraces a new boundary; the plant positions are **morphed** via MVC to follow the new shape. Implemented in `GardenARPlacementView` (issue #111, merged).

## MVC (Mean Value Coordinates)

Mathematical method (Floater, 2003) for expressing an interior point of a polygon as a weighted combination of its vertices, then reconstructing an equivalent point in another polygon using the same weights. Used in `GardenMorpher` to morph plant positions between the old boundary and the new boundary.

## ObjectCapture

Apple API (`PhotogrammetrySession`, iOS 17+, Area mode iOS 18+) that produces a textured 3D mesh from a set of photos. It is the non-LiDAR alternative to RoomPlan, considered for the non-LiDAR path of issue #140.

## Per-screen spec

Markdown document that describes a single main screen (hero screen) in detail: purpose, entry and exit points, widgets, edge cases, and dependencies. The full list is in [`screens/_index.md`](screens/_index.md).

## PhotogrammetrySession

See [**ObjectCapture**](#objectcapture).

## Plant

Entry in the MongoDB catalog: name, type, image URLs, multilingual translations, USDZ model URL, recommendation flags (`flags`/`PlantFlags`, including toxicity), `generated` indicator (whether the 3D model was generated by AI or not), `hasHeavy` (high-definition variant available), and `upAxis` (Y- or Z-up). The full structure is documented in [`architecture/04-data-model.md`](architecture/04-data-model.md).

## RelocationPhase

Swift enum defined in `GardenARPlacementView` that manages the five states of **manual replace**: `.scanning`, `.tracingBoundary`, `.morphingPreview`, `.adjusting`, and `.completed`. Diagrammed in `state-machines/relocation-phase.md` (Phase 3).

## RoomPlan

Apple framework (iOS 16+, LiDAR only) that scans a room in 3D and produces a structured model (walls, floors, doors, windows, furniture). Used in `LiDARScanWizardView` as an alternative to perimeter tracing. Check device support via `RoomCaptureSession.isSupported`.

## scanMethod

Enum held by `GardenWizardState` that determines the scan strategy: `.gardenPerimeter` (2D ground tracing, non-LiDAR) or `.roomScan` (RoomPlan, LiDAR only). Chosen at the wizard's `.scanMethod` step.

## ScreenSpec

See [**Per-screen spec**](#per-screen-spec).

## Sprint

Period of about one month materialized by a GitHub Milestone. A sprint groups the issues to deliver within the period; the current sprint is tracked via the repository's GitHub Milestones.

## Token (Firebase ID Token)

JWT bearer token signed by Firebase Auth, sent by the iOS application and the web in the `Authorization` header of every request to the backend. The backend validates it via the Firebase Admin SDK and extracts the Firebase `uid` from it.

## Thermal state

System temperature information exposed by iOS via `ProcessInfo.processInfo.thermalState`. Four levels: `.nominal`, `.fair`, `.serious`, `.critical`. From `.serious` onward, iOS imposes silent throttling. The `ARGarden/Quality/` module reads this signal when an AR session starts to choose `ARQuality`, and observes its subsequent transitions (`ARQualityObserver`) to notify the UI via `.arboreThermalCritical`. The `ThermalStateBanner` banner is shown as an overlay on this notification.

## TestFlight

Apple's beta distribution platform. An internal build is submitted for the team as well as for the Apple reviewer (account `appstore.review@arbore.app`). **External** distribution (public TestFlight link) is in place and approved by Apple. Details in [`operations/testflight-deploy.md`](operations/testflight-deploy.md).

## USDZ

Apple 3D model format (a ZIP archive containing a USD file and its textures). All plant models in the catalog are stored in USDZ format in `ArboreBackend/models/`, served via the `GET /models/:filename` endpoint, and rendered in AR via SceneKit.

## VPS (Fedora)

Single server that hosts the Go backend, the Python AI Generator, and the Next.js web front end via Docker Compose. Details in [`architecture/02-containers.md`](architecture/02-containers.md) and [`operations/vps-bootstrap.md`](operations/vps-bootstrap.md).

## WorldMap

See [**ARWorldMap**](#arworldmap).

## Wizard

Garden creation flow (`GardenWizardStep`) in eight to nine steps: intro → style → spaceType → exposure → maintenance → safety → (soil, if garden) → scanMethod → aiSuggestion. **`scanMethod` precedes `aiSuggestion`** (final step); there is **no** "summary" step. The `POST /gardens` is triggered at the tracing step (`scanMethod`), not at the end. Implemented in `QuestionnaireView`. Documented in [`screens/questionnaire-wizard.md`](screens/questionnaire-wizard.md) and [`flows/garden-creation.md`](flows/garden-creation.md).
